Basics in R: Part-2 (Data cleaning)

Data cleaning is a foundational step in any statistical analysis, as raw datasets are rarely structured in a form that is immediately ready for exploration or modeling. This chapter builds on the foundations introduced in Part 1 and focuses on practical, hands-on techniques for cleaning and manipulating data in R. Generate datasets from vectors

The datasets are the two dimensional array whereas vectors are the one dimensional array. The vector is the fundamental data structure used to store the data of the same types. We can convert vectors to dataframe using data.frame( ) In order to create vectors, we can use some important functions like c( ), seq( ), and rep( ).

Lets create 3 vectors and combine them to create dataframe.

id <- 1:10
age<-c(34,45,32,56,54,67,65,89,23,34)
sex <- c(rep("Male",5), rep("Female",5))


dt<-data.frame(id, age, sex) # make dataframe out of three vectors

class(dt) # check class of object dt
#> [1] "data.frame"

Data manipulation

Data manipulation in R involves various operations that transform and prepare data for analysis. The process includes tasks such as filtering rows, selecting variables, sorting, aggregating, merging, and reshaping data. In order to learn about data manipulation, lets explore mental health related data from Nepal Demographic and Health survey 2022 which is in the google drive.

# install.packages('gsheet')
# library(gsheet)

data<-gsheet::gsheet2tbl('https://docs.google.com/spreadsheets/d/1Sdp2kz0BD5x3nXTk8KlK6LtVy1MWnb_hcWuo67mrWgs')

Filtering

Filtering data in R is a common operation where you select a subset of rows based on certain conditions. Here’s how you can filter data:

# Filters dataset by Sex and only includes the data of females (Using base commands)
dtF <- data[data$Sex == "Female", ] 

# Filters dataset by sex and PHQ9 and includes data of females and who had PHQ-9 score greater than 10 (Using base commands)
dtFn <- data[data$Sex == "Female"  & data$PHQ9_Score > 10, ] 

# Filters dataset by Sex and only includes the data of females (Using dplyr and without piping)

dtF <- dplyr::filter(.data = data,data$Sex == "Female")

# Filters dataset by sex and PHQ9 and includes data of females and who had PHQ-9 score greater than 10 (Using dplyr and with piping)
dtFn <- data |> 
  filter(Sex == "Female" & PHQ9_Score > 10)

Selecting variables

Variables selection from the pool of variables is important to work efficiently.

# Selecting variables (age, sex and PHQ9_scores) (Using base commands and variable names)
sel_dt<- data[, c("Age","Sex","PHQ9_Score")] 

# Selecting variables (age, sex and PHQ9_scores) (Using base commands and using index)
sel_dt<- data[, c(6,7:10)] 

# Selecting variables (age, sex and PHQ9_scores) (Using dplyr package and variable names)
sel_dt <- data |> 
  dplyr::select(Age, Sex, PHQ9_Score)

# Selecting variables (age, sex and PHQ9_scores) (Using dplyr package and variable names)
sel_dt <- data |>

Grouping

Another common operation in R is grouping. Grouping is where you split the data into groups based on one or more variables. Functions or summaries can then be applied to each group.

# Using base commands
lapply(split(data$PHQ9_Score, data$Sex), mean) # The split function groups the PHQ-9 score by sex and the lapply function is applied to calculate the mean PHQ-9 score for each sex

# Using dplyr
library(dplyr)
data |> 
  group_by(Sex) |> 
  summarise(AvgPHQ9 = mean(PHQ9_Score))

Conditional computing

There are various built-in functions in R and some come with specific packages, that facilitate conditional operations in R.

# Using base commands
data$depression.severity <- ifelse(data$PHQ9_Score >= 10, "Moderate to Severe", "None to Mild") # Creating a depression severity variable based on the variable PHQ9_score
table(data$depression.severity)
#> 
#> Moderate to Severe       None to Mild 
#>                530              11823
data$agecat <- ifelse(data$Age < 20, "15-19",
                      ifelse(data$Age >= 20 & data$Age <= 24, "20-24",
                             ifelse(data$Age >= 25 & data$Age <= 29, "25-29", 
                                    ifelse(data$Age >= 30 & data$Age <= 34, "30-34", 
                                           ifelse(data$Age >= 35 & data$Age <= 39, "35-39",
                                                  ifelse(data$Age >= 40 & data$Age <= 44, "40-44", "45-49"))))))
table(data$agecat)
#> 
#> 15-19 20-24 25-29 30-34 35-39 40-44 45-49 
#>  2390  2116  1900  1642  1629  1438  1238

ifelse is a conditional function in R which takes in a certain condition and returns (or conducts a specified operations) certain values when the condition is TRUE or FALSE. In the above example, we recoded the variable Age into age categories.

# Using dplyr
data <- data |> 
  mutate(depression.severity.dplyr = case_when(PHQ9_Score >= 10 ~ "Moderate to Severe",
                                               TRUE ~ "None to Mild"))
table(data$depression.severity.dplyr)
#> 
#> Moderate to Severe       None to Mild 
#>                530              11823
data <- data |> 
  mutate(agecat.dplyr = case_when(Age < 20 ~ "15-19",
                                  Age >= 20 & Age <= 24 ~ "20-24",
                                  Age >= 25 & Age <= 29 ~ "25-29",
                                  Age >= 30 & Age <= 34 ~ "30-34",
                                  Age >= 35 & Age <= 39 ~ "35-39",
                                  Age >= 40 & Age <= 44 ~ "40-44",
                                  TRUE ~ "45-49"))
table(data$agecat.dplyr)
#> 
#> 15-19 20-24 25-29 30-34 35-39 40-44 45-49 
#>  2390  2116  1900  1642  1629  1438  1238

Renaming columns or variables

Some operations may require you to rename the columns or variables. Here’s how you can do this in R.

# Using base commands
colnames(data)[17] # Printing the 17th column name
#> [1] "Wealth"
colnames(data)[which(colnames(data) == "Wealth")] <- "Wealth.Quintile" # We want to change "Wealth" to "Wealth.Quintile"
colnames(data)[17] # Check if the column name is changed.
#> [1] "Wealth.Quintile"
# Using dplyr, let's rename Health_insurance to Health.Insurance

Merging dataframes

Merging datasets is a fundamental task in data analysis, enabling res./0 earchers and analysts to combine different data sources into a single dataset for comprehensive analysis. Before diving into specific functions, it’s essential to understand some key concepts: a) Types of merge and b) key columns.

Types of Merges

  • Inner Join: Returns only the rows with matching values in both datasets.

  • Outer Join: Can be further classified into:

    • Full Outer Join: Returns rows with matching values and those that do not match, filling missing matches with NA.

    • Left Outer Join: Returns all rows from the left dataset and the matched rows from the right dataset. Rows in the left dataset without a match in the right dataset have NA for the right dataset’s columns.

    • Right Outer Join: Returns all rows from the right dataset and the matched rows from the left dataset. Rows in the right dataset without a match in the left dataset have NA for the left dataset’s columns.

  • Cross Join: Returns the Cartesian product of both datasets, combining each row of the first dataset with each row of the second dataset.

Key Columns

Key columns are the variables used to match rows between two datasets. It’s crucial that these variables have the same type (e.g., both are integers or both are character) and ideally have the same name in both datasets for ease of merging.

To learn about different dataset merging methods, lets create dummy data frames and practice.

Transforming datasets

The datasets can long or wide type based on the way it was collected or on the nature/layout of the questionnaire. In a wide-format dataset, each observation is represented by a single row, and different variables are stored in separate columns. This format is often easy to read but may become impractical when dealing with a large number of variables. In a long-format dataset, each observation is represented by multiple rows, and different variables are stored in a single column indicating the variable type. This format is more flexible and is often preferred for various analyses. Let’s see how they look like and practice conversions from long to wide format and vice-versa.

Creating functions

Using Loops

Loops are programming structures that allow you to repeat a block of code multiple times. They are essential for automating repetitive tasks and iterating over elements like vectors, lists, or data frames. Here are two primary types of loops in R and their common uses:

For Loop:**

The for loop is used when you know the number of iterations in advance. It iterates over a sequence (which can be a vector or a sequence generated by functions like seq()).

# Example: Printing numbers from 1 to 5 using a for loop
for (i in 1:5) {
  print(i)
}
#> [1] 1
#> [1] 2
#> [1] 3
#> [1] 4
#> [1] 5

While Loop

The while loop is used when you do not know the number of iterations in advance but have a condition that, when met, stops the loop.

# Example: Printing numbers from 1 to 5 using a while loop
i <- 1
while (i <= 5) {
  print(i)
  i <- i + 1
}
#> [1] 1
#> [1] 2
#> [1] 3
#> [1] 4
#> [1] 5

Loop control statements provide mechanisms to alter the flow of execution within loops. The break statement allows for the premature termination of a loop, while the next statement skips the remaining code for the current iteration and proceeds to the next iteration. These statements offer flexibility in managing loop execution based on specific conditions.

# Example: Using break and next in a for loop
for (i in 1:10) {
  if (i == 5) {
    break  # Exit the loop when i is 5
  }
  if (i %% 2 == 0) { # %% operator is the modulo operator. It returns the remainder of the division of one number by another.
    next  # Skip the rest of the code for even numbers
  }
  print(i)
}
#> [1] 1
#> [1] 3

Missing Data Handling

Missing data are common in real-world datasets and can arise for many reasons, including nonresponse, data-entry errors, skipped survey questions, equipment failure, or loss to follow-up. How missing data are handled can have an important effect on the results of an analysis.

Therefore, missing observations should not automatically be deleted or replaced without first considering why the data are missing and how the missingness may affect the research question.

In R, missing values are commonly represented by NA. Empty strings ("") may also occur in character variables and can represent missing information, although they are not automatically treated as NA by R.

This chapter introduces several approaches to identifying and handling missing data. We will focus on:

  1. Identifying and removing missing values
  2. Constant value imputation
  3. Mean and median imputation
  4. Model-based imputation
  5. Multiple imputation
  6. Choosing an appropriate missing-data strategy

Identifying and Handling misisng or Blank Values

Before deciding how to handle missing data, the first step is to identify where missing observations occur.

Let us begin by creating two simple vectors. The first contains an empty string, while the second contains an NA value.

blanks <- c("John", "Jane", "")
nas <- c(NA, "Jane", "Joe")

print(blanks)
#> [1] "John" "Jane" ""
print(nas)
#> [1] NA     "Jane" "Joe"

Identifying NA Values

The is.na() function identifies missing values represented by NA.

is.na(nas)
#> [1]  TRUE FALSE FALSE

The result is a logical vector containing TRUE and FALSE values. A TRUE value indicates that the corresponding observation is missing.

We can use is.na() to extract only the missing observations:

only_nas <- nas[is.na(nas)]

print(only_nas)
#> [1] NA

More commonly, we want to retain observations that are not missing. The ! operator means “not.”

no_nas <- nas[!is.na(nas)]

print(no_nas)
#> [1] "Jane" "Joe"

Thus:

  • is.na(x) identifies missing observations, while
  • !is.na(x) identifies observations that are not missing.

Identifying Blank Strings

An empty string ("") is different from NA.

We can identify empty strings using the equality operator ==.

blanks == ""
#> [1] FALSE FALSE  TRUE

We can extract only the blank observations:

only_blanks <- blanks[blanks == ""]

print(only_blanks)
#> [1] ""

Similarly, we can retain observations that are not blank:

no_blanks <- blanks[blanks != ""]

print(no_blanks)
#> [1] "John" "Jane"

It is often useful to convert blank strings to NA so that all missing observations can be handled consistently.

blanks[blanks == ""] <- NA

print(blanks)
#> [1] "John" "Jane" NA

We can now use is.na() to identify these observations:

is.na(blanks)
#> [1] FALSE FALSE  TRUE

Counting Missing Values

Before deciding how to handle missing data, it is useful to determine how many missing observations exist.

For a vector, we can use:

sum(is.na(nas))
#> [1] 1

The proportion of missing observations can be calculated using:

mean(is.na(nas))
#> [1] 0.3333333

For a data frame, colSums() can be used to count missing observations in each variable.

students <- c("John", "Jane", "Joe", "Janet")
scores <- c(100, 80, NA, 90)
age <- c(20, NA, 22, 21)

df <- data.frame(
  student = students,
  score = scores,
  age = age
)

print(df)
#>   student score age
#> 1    John   100  20
#> 2    Jane    80  NA
#> 3     Joe    NA  22
#> 4   Janet    90  21

Count the number of missing values in each variable:

colSums(is.na(df))
#> student   score     age 
#>       0       1       1

Calculate the percentage of missing values:

colMeans(is.na(df)) * 100
#> student   score     age 
#>       0      25      25

Removing Observations with Missing Values

One simple approach to missing data is to remove observations containing missing values.

The na.omit() function removes rows containing one or more NA values.

students <- c("John", "Jane", "Joe")
scores <- c(100, 80, NA)

df <- data.frame(
  student = students,
  score = scores
)

print(df)
#>   student score
#> 1    John   100
#> 2    Jane    80
#> 3     Joe    NA

Remove observations containing missing values:

df_complete <- na.omit(df)

print(df_complete)
#>   student score
#> 1    John   100
#> 2    Jane    80

Although na.omit() is convenient, deleting observations should not automatically be the default approach.

If missingness is related to characteristics of the participants or variables being studied, complete-case analysis can introduce bias.

Constant Value Imputation

Constant value imputation replaces missing observations with a predetermined value.

For example:

students <- c("John", "Jane", "Joe")
scores <- c(100, 80, NA)

df <- data.frame(
  student = students,
  score = scores
)

print(df)
#>   student score
#> 1    John   100
#> 2    Jane    80
#> 3     Joe    NA

If we know that the missing value represents a score of zero, we can replace it with 0:

df$score[is.na(df$score)] <- 0

print(df)
#>   student score
#> 1    John   100
#> 2    Jane    80
#> 3     Joe     0

However, researchers should be careful when using zero as an imputation value.

A missing value and a zero value are not necessarily the same thing.

For example:

  • 0 hospital visits means that the person had no hospital visits.
  • NA hospital visits means that the number of visits is unknown.

Therefore, zero should only be used when there is a substantive reason to believe that the missing value represents zero.

Mean Imputation

Another simple approach is to replace missing values with the mean of the observed values.

Suppose we have data on the number of hours employees spend performing a particular task:

employees <- c("John", "Jane", "Joe", "Janet")
hours_spent <- c(12, 14, NA, 9)

df <- data.frame(
  employee = employees,
  hours_spent = hours_spent
)

print(df)
#>   employee hours_spent
#> 1     John          12
#> 2     Jane          14
#> 3      Joe          NA
#> 4    Janet           9

Calculate the mean using:

mean_value <- mean(
  df$hours_spent,
  na.rm = TRUE
)

print(mean_value)
#> [1] 11.66667

Replace the missing observation with the mean:

df$hours_spent[
  is.na(df$hours_spent)
] <- mean_value

print(df)
#>   employee hours_spent
#> 1     John    12.00000
#> 2     Jane    14.00000
#> 3      Joe    11.66667
#> 4    Janet     9.00000

Mean imputation is easy to implement but has important limitations. When multiple missing observations are replaced with the same mean:

  • variability in the data is reduced;
  • the distribution may be distorted;
  • relationships between variables may be weakened; and
  • standard errors may be underestimated.

Therefore, mean imputation is generally not recommended as the primary approach for substantial missing data in inferential analyses.

Median Imputation

The median can also be used to replace missing values.

Median imputation may be useful when a variable is highly skewed or contains extreme values.

Reset the variable:

df$hours_spent <- hours_spent

print(df)
#>   employee hours_spent
#> 1     John          12
#> 2     Jane          14
#> 3      Joe          NA
#> 4    Janet           9

Calculate the median:

median_value <- median(
  df$hours_spent,
  na.rm = TRUE
)

print(median_value)
#> [1] 12

Replace the missing observation:

df$hours_spent[
  is.na(df$hours_spent)
] <- median_value

print(df)
#>   employee hours_spent
#> 1     John          12
#> 2     Jane          14
#> 3      Joe          12
#> 4    Janet           9

Median imputation is simple and less sensitive to extreme values than mean imputation. However, it still does not account for uncertainty surrounding the missing value and can distort relationships between variables.

Model-Based Imputation

Instead of replacing all missing observations with the same value, we can use information from other variables to estimate missing values.

For example, consider two variables, x and y:

y <- c(10, 8, NA, 9, 4, NA)
x <- c(8, 6, 9, 7, 2, 12)

df <- data.frame(
  y = y,
  x = x
)

print(df)
#>    y  x
#> 1 10  8
#> 2  8  6
#> 3 NA  9
#> 4  9  7
#> 5  4  2
#> 6 NA 12

The outcome variable y contains two missing observations, while x is observed for every individual.

We can use linear regression to model the relationship between x and y:

model <- lm(
  y ~ x,
  data = df
)

summary(model)
#> 
#> Call:
#> lm(formula = y ~ x, data = df)
#> 
#> Residuals:
#> 1 2 4 5 
#> 0 0 0 0 
#> 
#> Coefficients:
#>             Estimate Std. Error t value Pr(>|t|)    
#> (Intercept)        2          0     Inf   <2e-16 ***
#> x                  1          0     Inf   <2e-16 ***
#> ---
#> Signif. codes:  0 '***' 0.001 '**' 0.01 '*' 0.05 '.' 0.1 ' ' 1
#> 
#> Residual standard error: 0 on 2 degrees of freedom
#>   (2 observations deleted due to missingness)
#> Multiple R-squared:      1,  Adjusted R-squared:      1 
#> F-statistic:   Inf on 1 and 2 DF,  p-value: < 2.2e-16

We can use the fitted model to predict values of y for observations where y is missing:

missing_y <- is.na(df$y)

imputed_values <- predict(
  model,
  newdata = data.frame(
    x = df$x[missing_y]
  )
)

print(imputed_values)
#>  1  2 
#> 11 14

Insert the predicted values into the missing positions:

df$y[missing_y] <- imputed_values

print(df)
#>    y  x
#> 1 10  8
#> 2  8  6
#> 3 11  9
#> 4  9  7
#> 5  4  2
#> 6 14 12

This approach is more informative than replacing every missing value with the overall mean because the imputed value depends on information from another variable.

However, this is single model-based imputation, not true multiple imputation.

Multiple Imputation

Multiple imputation is a more advanced approach to handling missing data.

Instead of creating one completed dataset, multiple imputation creates several datasets in which missing values are replaced with plausible values.

Each completed dataset is then analyzed separately, and the results are combined.

The basic process is:

  1. Identify missing observations.
  2. Create multiple plausible versions of the missing values.
  3. Analyze each completed dataset.
  4. Combine the estimates.
  5. Incorporate uncertainty caused by missing data.

One commonly used R package for multiple imputation is mice.

library(mice)

Create a dataset containing missing values:

set.seed(123)

  age = c(25, 31, NA, 45, 52, 38, NA, 29),

Analyzing Multiply Imputed Data

The completed datasets should not simply be combined into one large dataset.

Instead, the analysis is performed separately within each imputed dataset, and the results are then pooled.

For example, suppose we want to model systolic blood pressure as a function of age and BMI:

fit <- with(
  imp,
  lm(
    systolic_bp ~ age + bmi
  )
)

The results can then be pooled:

pooled_results <- pool(fit)

summary(pooled_results)
#>          term   estimate  std.error statistic       df   p.value
#> 1 (Intercept) 88.0628836 39.4219110 2.2338563 1.166318 0.2386250
#> 2         age  0.6924738  0.5526748 1.2529498 1.771319 0.3504498
#> 3         bmi  0.5988944  2.1725796 0.2756605 1.034357 0.8275871

Pooling accounts for:

  • uncertainty within each completed dataset; and
  • uncertainty caused by the missing data.

This is one of the major advantages of multiple imputation over simple mean or median imputation.

Missing Data Mechanisms

The appropriate missing-data method depends partly on why the data are missing.

Three commonly discussed missing-data mechanisms are described below.

Missing Completely at Random (MCAR)

Data are missing completely at random (MCAR) when the probability of an observation being missing is unrelated to both observed and unobserved data.

For example, suppose several laboratory samples are accidentally lost because of a random equipment failure, with no relationship to participant characteristics.

Under MCAR, complete-case analysis may produce unbiased estimates, although it reduces the available sample size.

Missing at Random (MAR)

Data are missing at random (MAR) when missingness is related to variables that have been observed. For example, suppose younger participants are less likely to report income. If age is available for everyone, the relationship between age and missing income can potentially be incorporated into an imputation model.

Many multiple-imputation methods rely on the MAR assumption.

Missing Not at Random (MNAR)

Data are missing not at random (MNAR) when the probability of missingness depends on information that remains unobserved. For example, individuals with particularly high incomes may be less likely to report their income because their income is high.

MNAR is more difficult to address because the information related to missingness is itself unavailable. Sensitivity analyses and specialized missing-data models may therefore be necessary.

Choosing an Appropriate Missing-Data Method

There is no single missing-data method that is appropriate for every dataset.

Situation Possible approach
Missing value genuinely represents zero Constant-value imputation
Very small amount of MCAR missingness Complete-case analysis
Simple exploratory analysis Mean or median imputation
Missingness related to observed variables Multiple imputation
Complex epidemiological analysis Carefully specified multiple imputation
Suspected MNAR mechanism Sensitivity analysis or specialized models

The decision should consider:

  • Amount of missing data
  • Pattern of missingness
  • Type of variable
  • Study design
  • Analysis model
  • Plausible missing-data mechanism
  • Potential for missingness to introduce systematic bias.

Practical Recommendations

When working with missing data in R, the following workflow is recommended.

Step 1: Identify Missing Values

is.na(df)

Step 2: Count Missing Values

colSums(is.na(df))

Step 3: Calculate the Percentage of Missing Values

colMeans(is.na(df)) * 100

Step 4: Check for Other Missing-Value Codes

Some datasets use values such as:

  • ""
  • "."
  • "99"
  • "999"

These should only be treated as missing when the study documentation or codebook confirms that they represent missing information.

For example:

df$variable[df$variable %in% c("", ".", "99", "999")] <- NA

Step 5: Examine the Pattern of Missingness

For datasets with multiple variables, examine which variables tend to be missing together.

md.pattern(df)

Step 6: Consider Why the Data Are Missing

Ask whether the missingness is likely to be:

  • MCAR
  • MAR or
  • MNAR.

Step 7: Select an Appropriate Method

Do not automatically remove observations or replace missing values with zero.

Consider multiple imputation when appropriate.

Step 8: Perform Sensitivity Analyses

When conclusions may depend on assumptions about missingness, perform sensitivity analyses using alternative reasonable assumptions.

Step 9: Document the Method

Clearly report: - how much data were missing? - which variables contained missing data? - how missingness was assessed? - the method used to handle missing data. - variables included in the imputation model - the number of imputations - assumptions about missingness and - any sensitivity analyses performed.
